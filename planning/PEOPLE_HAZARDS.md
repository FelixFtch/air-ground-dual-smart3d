# Temporary people OHZ contract

`perception.hazards.build_hazards(document, robot_profile, sim_time, epoch, scene_id)` converts `air_ground.people/v1` observations into a sorted list of `air_ground.people_hazard/v1` constraints. The owner passes that list as native `people_hazards`, to `check_hazard_segment(start_xyz, end_xyz, hazards, sim_time)`, and to RViz. The guard returns a blocking hazard or `None`; malformed data raises `ValueError`. Consumers must not add another robot radius.

Centers and principal axes use the shared map basis. The output is configuration-space geometry for the robot reference point: body offsets have already been subtracted. Each object specifies `dimension`, `shape`, `center_xyz`, orthonormal `axes_xyz`, `semi_axes_m`, scene epoch/id, profile id, evidence source keys, capture/reference/expiry times, horizontal velocity quality, unknown vertical velocity, measured partial extent, applied prior, and robot envelope. In 2D the third semi-axis is zero, center z is profile planar z, and the collision predicate ignores z. Observations whose measured/prior interval cannot overlap the ground robot's physical z band are omitted.

Default profile policy (`people_hazard`) is `horizon_s: 1.0`, `position_uncertainty_m: 0.15`, `vertical_padding_m: 0.85`. The latter adds 0.85 m at each end of the **visible surface quantile** z range; this is a conservative profile prior, not measured human height. The uncertainty allowance is explicitly uncalibrated. A profile can set either allowance to zero. No vertical velocity is estimated: nonzero z placeholder or claimed valid z speed is rejected. Invalid horizontal speed never creates directed prediction.

Let `rho = hypot(measured_hx, measured_hy) + hypot(robot_hx, robot_hy) + uncertainty`, `z = measured_hz + vertical_padding + robot_hz`, and `d = valid_XY_speed * horizon`. For ground robots, base radii are `R=rho`; for the UAV, `R=sqrt(2)*rho` and `Z=sqrt(2)*z`. The latter ellipsoid encloses the finite cylindrical body envelope. Set `a = 1 + d/(2R)`; semi-axes are `(R*a, R*sqrt(a))` in 2D and `(R*a, R*sqrt(a), Z*sqrt(a))` in 3D, centered at the prediction midpoint. The normalized swept-unit-ball support is enclosed because the squared support difference is `h*(1-|c|)^2 >= 0`, where `h=d/(2R)`. This avoids the nonconservative `minor=rho` ellipse shortcut.

Both Python and Rust transform each segment endpoint into the unit-ball frame and exactly minimize squared distance along the segment, comparing to `1 + 1e-6` for f32 boundary tolerance. No sphere approximation or sampled path steps enter the collision predicate. The native enclosing sphere serves only broadphase/recovery-region queries. RViz should use the normalized center, axes and twice the semi-axes as full scale.

The source registry position is already at `position_reference_sim_time`; reader extrapolation is capped at capture+1 s to avoid double prediction. Expired people are omitted, future/identity-invalid input is rejected. Native rejects explicit expired inputs; an omitted `people_hazards` field retains installed entries only until their simulation expiry, while an explicit empty array removes them immediately.

The native worker preserves SMART<f32,2/3>, supplies the normalized affine geometry to its OHZ API, and checks that same geometry for tree edges and final paths. New/moved constraints prune the retained tree through the existing checker; removals/expiry enqueue their old bounded region for reconnection. `people_revision` advances for changed geometry, not lease/metadata renewal. Metrics distinguish actual changes, metadata-only refreshes, and clear-region work. No prediction is written into OctoMap, and removing a person constraint never deletes actual sensor occupancy.

Validation: `tests/test_people_hazards.py` verifies support containment, finite 3D height, velocity/time/identity gates, ground height filtering, offset handling, and no double extrapolation. `planning/tests/people_hazards.rs` verifies Python-generated shared fixtures (`174` segments), invalid native input rejection, TTL-only refresh, and expiry/path recovery in the same SMART2 and SMART3 trees. Build/test artifacts belong in `/tmp`, not over the running binary.

The worker exports `local_reaction_radius_m` from the same 4.0 m constant passed to SMART and `local_reaction_center_xyz` from its accepted current state. These describe the native LRZ at output `sim_time`; display a planar circle for dimension 2 and a sphere for dimension 3. Do not substitute a display-only fixed radius or a newer robot pose.
